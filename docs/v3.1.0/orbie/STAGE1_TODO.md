## 实现

- [ ] 增加最小 Orbie 绑定存储和依赖注入；I/O 失败可见，不回退到另一份空绑定继续创建。
- [ ] 增加应用内「打开 Orbie」入口，显式创建后重复打开定位同一持久目标。
- [ ] 复用现有 New Agent／Provider 选择、目录检查、shell 集成及窗口创建，不新增独立 Agent 启动器。
- [ ] 创建前保存意图，创建处理中防止重复；回包不明先核对，无法确认时保留待核对状态。
- [ ] 接入单步工作流，引用现有 run／invocation，不复制输入账本、超时恢复或原生完成解析逻辑。
- [ ] 区分面板草稿、终端草稿、已发送输入及最终结果；忙碌／提问／授权时不覆盖输入。
- [ ] App 重启后解析既有持久目标；进程或原生会话不匹配时拒绝投递并显示现有恢复入口。
- [ ] 关闭入口不停止 Agent；停用功能不删除绑定、用户文件或普通标签。

## 验证

- [ ] 存储往返、损坏／不可写、同目标重复打开、创建成功但回包未确认。
- [ ] Codex、Claude 各完成首条消息及下一轮；记录实际 Provider 与 CLI 版本。
- [ ] 原生首次会话尚未确认、手动输入发生在准备与写入之间、已有其他工作流占用。
- [ ] 提问或审批等待时能转到普通终端继续；没有额外伪造 Enter／Esc。
- [ ] 进程替换、复用 pane ID、同名标签、会话切换均不能承接旧投递权限。
- [ ] App 重启且 tmux 存活时使用原 Orbie，不重发历史消息；tmux 不存在时不抢在现有恢复前重建。
- [ ] 相关单元回归、SwiftFormat、边界检查及 Mac 编译通过；原生运行验证使用隔离 App 和私有 tmux。
