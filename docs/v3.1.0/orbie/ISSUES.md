## 阶段 1 收敛（2026-11-13）

- O-01／O-02：本机显式创建、现有 Agent／Provider 表单，私有原生首条／下一轮及审批证据已记录；不承诺所有真实账号、Provider 或插件版本均已验收。
- O-04：`agents/main/` 只补缺失的 AGENTS／CLAUDE 角色说明，不修改原生记忆开关或用户配置；测试 CLI 版本见阶段清单。
- O-07：绑定与请求引用持久化，写入不明不重发。2026-11-14 调整 Orbie 的身份语义：同一持久 Host／window／pane 内自动采用重新核验的当前运行态，进程／原生会话用于单次请求核验，不再要求 Orbie 手动 Reconnect；未完成消息仍需核查。签名 App 重启且 tmux 存活的接续已验收；整机重启和 tmux 拓扑重建仍留给既有恢复与阶段 6。此次改动的回归证据见 STAGE1_TODO。
- O-08：本阶段每条面板消息是普通单步工作流，历史记录仍可从 Workflows 查看；后续任务索引呈现及归档／删除联动在阶段 2 收敛，不另造隐藏类型或第二份投递状态机。
- 既有 `NewTabMenuTests.keyboardSelection` 的三种离屏键盘参数在扩展检查中失败，相关源码未变；未宣称已修复。Orbie 与本次受影响的创建表单／模型默认值定向回归及实际签名 App 操作通过，见阶段清单的日志与边界。
- Round 1 P2「移动 pane 后无法重新连接原 Orbie」已修复：优先匹配原进程并更新窗口路由；64 项定向回归、Mac 编译和隔离签名 App 的实际移动／继续消息／重启验收通过。当时的手动会话确认策略已由上述持久目标关联修订取代，旧请求核验保留。证据与未测边界见 STAGE1_TODO 的 Round 1 修复记录。

## 阶段 2 收敛（2026-11-13）

- O-05／O-08：采用两个活跃任务、无自动队列；归档保留终端、材料及执行结果。任务与工作流账本通过 run ID 关联，后台仅订阅一个账本变更流，不引入第二套投递状态。
- O-07：New／Fork 的创建意图先持久化，创建标识在启动 Agent 前写入新 pane；丢回包先核对，不自动重建或重发。实例／原生对话变化需明确重连／关联，已有工作流占用仍由原通道拒绝。
- 原生验收发现并修复编辑区被后台刷新／自动保存短暂禁用，以及 Fork 创建标识在嵌套 tmux guard 中被当作 shell 参数的问题。实际 tmux 回归确认新 pane 有标识且源 pane 不变。
- 隔离签名 App 中，真实 Codex 0.167.1／Claude Code 2.1.319 均通过 New 与 Fork 上下文、报告交接、移动标签导航、重启不重发及重启后继续同一任务。详细命令、结果与边界见 [STAGE2_TODO.md](STAGE2_TODO.md)。
- 阶段 2 未验收自然语言查找和全局快捷键；两者的后续实现见 STAGE3_TODO。选区图片、长期记忆、整机／tmux 拓扑重建及跨设备专用入口仍按后续阶段推进，不因早期阶段验收而视为已完成。
- Round 1 两项 P2 已做局部修复：创建关联保留并校验原 server，待确认请求按账本原始输入清理草稿，保留新追问。两组修复前复现及修复后的 103 项定向回归记录见 STAGE2_TODO 的 Round 1；本轮未重跑完整 E2E。
