# Agent Browser 演进 TODO

记录日期：2026-09-28，更新至 2026-09-29。状态：页面能力扩展已分项实施，产品功能及外部接入仍待实施。以逐项效果验收为准；本文件不授权安装扩展、访问外部浏览器或发布。

## 已确认的定位与边界

- 默认定位仍是 **CtrlX 内嵌 Agent Browser**，与用户日常浏览器的 profile 隔离；不替换原有 WebKit「New Browser」。
- 保留同一 session 内展示、Codex 进程实例与标签归属校验，以及 CtrlX 内部共享持久化登录态。共享 profile 不等于各 Agent 的账号数据隔离。
- 保留默认 Vercel agent-browser 引擎和可选的原 CtrlX 引擎；继续使用 `ctrlx browser`，不要求特殊 Codex 启动命令。
- 非扩展方式使用 CDP，并不天然比扩展方式少能力。当前缺口应逐项区分：CLI 未暴露、网关方法/事件过滤、目标/子会话未适配、引擎限制、CEF/Chromium 运行时差异。
- 将「实例隔离」与「页面能力」分开设计：不以安全为由永久排除正常页面能力，也不通过取消归属校验或开放全局调试入口来补齐功能。

当前实现与已知限制以 [架构说明](agent-browser.md)、[双引擎说明](agent-browser-engines.md) 和 [能力审计](agent-browser-capability-audit.md) 为准。审计中的历史记录不能当作当前支持清单。

## 工作分类

- **A｜仅需开放入口**：上游已有实现，且现有 CtrlX 网关已有相应效果证据；只需开放受控命令/参数、补帮助与回归，不涉及新的文件语义、目标路由或生命周期处理。
- **B｜上游已有，需额外适配**：复用引擎能力，但还需 CLI 参数/产物处理、CDP 方法与事件、子会话、启动配置或运行时依赖等工作；不是改白名单即可。
- **C｜CtrlX 新增产品开发**：需要 CtrlX 自己实现 UI、流程、权限或持久化；可复用引擎原语，不等于引擎已有完整产品功能。
- **D｜待核实**：当前固定引擎版本、CEF 运行时或验收证据不足，实施前先验证，不能先归入 A。
- **已开放 / 保持限制**：分别表示已有能力的回归任务，以及不应直接透传的全局操作。

分类依据：2026-09-28 固定 `agent-browser 0.38.1` 的源码、CLI/网关和隔离 CEF 效果验收。A/B 是工作性质，不是完成状态；下列“已接入”仍只覆盖注明的子集。当前测试范围与证据统一维护在 [能力审计](agent-browser-capability-audit.md)。

## 1. 产品功能

### 录制操作生成 Skill〔C〕

上游已有点击、输入、快照等原语和 `record` 视频录制，但不能将其当作“录制人工操作并生成 Skill”的完整实现；步骤采集、参数化、脱敏和生成流程由 CtrlX 补充。

- [ ] 提供显式开始、暂停、结束录制，仅记录用户选定的标签及授权范围内的后续页面。
- [ ] 将导航、点击、输入、等待和验证步骤转为基于 `ctrlx browser` 的可复用 Skill；优先使用语义定位，避免只保存屏幕坐标或过期元素引用。
- [ ] 支持保存前预览、编辑和参数化；不固化标签 ID、进程身份、临时路径或当前登录凭据。
- [ ] 对密码、验证码、令牌及其他敏感输入做排除/脱敏；实际提交、上传等副作用步骤明确标注，不在生成时自动重放。
- [ ] 验收：在隔离测试站点录制多步流程，由新的真实 Codex 实例读取生成的 Skill，使用不同参数完成任务，并断言页面最终结果。

这里的「操作录制」指结构化交互步骤，不等于视频录屏；已接入的有界录像及限制见第 2 项。

### 明确的人机接管〔C〕

上游提供 `confirm/deny` 动作确认，但不等于 CtrlX 标签的人工接管、队列暂停与交还机制。

- [ ] 在标签中清晰显示所属 Agent、当前控制者及执行/暂停/等待人工状态。
- [ ] 提供人工接管与明确交还入口；接管后阻止新的 Agent 写操作，处理待执行队列，说明已经发出的操作不一定能撤销。
- [ ] 交还前重新获取页面状态，废弃导航前的引用，不自动重试结果未知的提交操作。
- [ ] 验收：Agent 操作中接管、人工登录/导航后交还、关闭标签、Agent 退出；其他实例和标签不受影响。

### 选择页面作为上下文〔C；复用已开放能力〕

上游及 CtrlX 已有 `read/snapshot/eval` 等读取能力；页面选择、预览、目标 Agent 路由和上下文交付仍需产品层实现。

- [ ] 支持显式选择所属/已授权页面、选中文本或页面片段，并指明接收上下文的 Agent；不根据当前焦点猜测目标。
- [ ] 提供发送前预览，携带标题、URL、采集时间和来源；限制大小并明确标记截断、导航后过期等状态。
- [ ] 区分「将页面内容交给 Agent」与「允许 Agent 控制页面」，不因选择上下文自动扩大控制权限；网页文本按不可信内容处理。
- [ ] 验收：单页、多页、选区、动态页面、页面关闭/导航，以及跨实例拒绝；不意外读取其他标签或敏感输入。

- [ ] 核查 DOM/可访问性树/Shadow DOM、富文本输入、拖放、触摸/设备模拟、地理位置权限、worker 等场景；分别记录引擎与 CEF 版本的实际边界。
- [ ] 评估页面级 Debugger/Profiler 及诊断能力；对可能跨页或跨进程采集的 Tracing 单独审查，不直接开放整个共享浏览器。
- [ ] 保持全局清 Cookie、整份 profile 导出、任意目标控制等操作的边界；若确有业务需求，单独设计授权与作用域，不当作普通页面能力放行。

### 建立持续验收矩阵

- [ ] 每项能力记录：上游/CEF/Chromium 版本、引擎、公共命令及参数、页面/目标范围、预期效果、测试证据和当前结论。
- [ ] 结论分为「已通过效果断言」「部分支持」「未实现」「未验证」「明确不支持」；不得将成功响应或未报错记为完整通过。
- [ ] 使用本地可控站点覆盖 iframe、SPA、延迟加载、重定向、网络失败、中文输入、文件、权限及弹窗；断言 DOM、事件、网络记录或产物内容。
- [ ] 回归多 session/多 Agent 并行、同页串行、跨实例拒绝、旧授权失效、超时取消、崩溃/重启及共享登录态；验证接管时不会继续执行排队写操作。
- [ ] 增加真实 Codex 端到端验收：Skill 发现 → CLI 调用 → 内嵌页面效果 → 结果回读；身份夹具测试单独标记，不冒充真实 Agent 验收。
- [ ] 在隔离签名测试 App/profile 中执行自动化，保留日志与必要的截图/产物；不向用户正在运行的任务或日常浏览器注入测试操作。

「全面支持及测试」指建立可追踪、逐项验证的覆盖面，不承诺所有 CDP 命令、上游平台和参数无条件开放。

## 3. 可选接入外部浏览器〔B＋C〕

上游已有 `connect` / `--cdp` / `--auto-connect` 等外部连接能力，但 CtrlX 仍需补目标选择、授权、实例映射、断线撤销和 UI。若选择扩展桥接，还需验证或实现桥接服务；不是直接放开上游自动连接选项。

- [ ] 作为后续可选模式评估，默认仍为内嵌浏览器；外部接入与 Vercel/原 CtrlX 引擎选择是两个不同维度。
- [ ] 比较浏览器扩展桥接与用户显式授权的 CDP 连接；先确定支持的浏览器、profile、身份认证和权限撤销机制，不预设必须采用扩展。
- [ ] 由用户明确选择外部浏览器及可接管标签/标签组，默认关闭；不能自动扫描接管所有标签、复制系统 profile 或静默继承日常浏览器权限。
- [ ] 保持 `ctrlx browser` 的统一使用方式，并明确显示内嵌/外部目标；外部网页仍在外部浏览器中，不承诺嵌入 CtrlX，也不自动切换连接方式。
- [ ] 延续实例归属和人机接管机制，覆盖扩展卸载/禁用、桥接断线、浏览器重启、标签转移及授权撤销；错误时不回退到另一个浏览器执行。
- [ ] 初期仅评估同一 Mac 的外部浏览器；跨设备/Relay 浏览器控制不包含在本 TODO 的默认范围。
- [ ] 验收使用隔离测试 profile；访问真实日常 profile、安装扩展或读取既有页面前单独取得用户授权。

## 建议实施顺序与完成标准

1. 先完成第 2 项的分层能力矩阵和回归基线，确认 A/B/C/D 分类，同时规划人机接管边界。
2. 在第 2 项中逐项完成“上游复用 → 必要适配 → 公共入口开放 → 效果验收”，优先跨进程 frame 等正常网页缺口。
3. 交付人机接管、页面上下文选择、操作录制生成 Skill，并完成真实 Codex 验收。
4. 外部浏览器接入作为独立可选阶段，不阻塞内嵌能力完善。

每次只勾选已满足验收条件的条目，并在此记录对应提交、测试范围及证据位置。仅记录 TODO 不触发构建、安装、提交或发布。
