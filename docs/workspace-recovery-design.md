# CtrlX 重启后的工作现场恢复设计

记录日期：2026-10-15。代码核对基线：`a330a3b`（3.0.74）。

状态：正在按本文实现，尚未完成整体功能或验收。本文记录电脑重启后的恢复目标、边界和验收条件；当前已实现的布局行为仍以[布局持久化文档](folder-layout-persistence-plan.md)和源码为准。

实现进度另见 [工作现场恢复实施计划](v3.0.76/IMPLEMENTATION_PLAN.md)。底层测试通过不代表完整恢复功能已接入或通过重启验收。

## 1. 产品目标

电脑重启后重新打开 CtrlX，窗口、会话、分屏和标签回到原来的位置；能够确认身份的 Agent 重新打开原对话，普通终端回到原目录的 shell。

CtrlX 保存工作区结构与恢复入口，Agent 使用自己的持久化记录恢复对话。两者不要求采用同一个保存时间点，也不需要 CtrlX 复制整份 Agent 对话历史。

用户可以接受有一定延迟的布局快照。现有实现已有 2 秒保存检查，因此建议继续使用秒级保存，不增加保存频率设置。性能目标是只处理变化的轻量元数据，不周期性捕获终端输出或扫描完整对话历史；实际成本需要实现后测量。

## 2. 恢复范围

| 对象 | 目标行为 | 边界 |
| --- | --- | --- |
| Mac 原生窗口 | 恢复主窗口、独立窗口、标签归属、位置和大小 | 原显示器不可用时，把窗口放回可见屏幕；首版不承诺恢复 macOS Spaces 归属 |
| 会话列表 | 恢复会话名称、已有显示属性、手动顺序和上次选择 | 自动排序仍根据恢复后的真实状态计算，不恢复旧 Working 状态来维持顺序 |
| CtrlX 分栏 | 恢复左右分栏、比例、各栏标签顺序、选中标签和焦点侧 | 同目录的不同会话分别恢复 |
| 终端内部分屏 | 恢复 tmux window 内的 pane 树、比例、各 pane 目录和选中 pane | 与 CtrlX 左右分栏分别建模，两层都需要保存 |
| Agent pane | 在对应目录、配置来源下，按准确会话 ID resume | 恢复对话，不重放 CtrlX 保存的旧提示词、命令或审批 |
| 普通 terminal pane | 在原目录启动正常 shell | 不重放执行中的命令，不保证恢复临时环境变量、虚拟环境、SSH 连接或 TUI 内存 |
| Files / Git | 恢复浏览目录、文件或预览位置，并重建正确的来源关联 | 文件已删除时提示缺失，不改用另一个文件；共享 Files 由 Host 重建身份 |
| Browser | 后续按 URL 重开页面，沿用有效的浏览器配置和登录数据 | URL 重开不等于页面内存恢复；未提交表单、旧自动化授权和控制租约不直接恢复 |
| CtrlX 输入框 | 保存并恢复尚未发送的草稿，绑定到原来的目标 pane | 绝不自动发送；直接输入到终端程序中的未提交文字不保证恢复 |

首版核心范围为 Mac 本机会话、两层分屏、独立窗口、普通 shell、Codex / Claude Code 对话、Files / Git 和 CtrlX 草稿。Browser 的完整接入、模拟器和调试器运行状态、终端历史屏幕留作后续扩展，不能在首版宣传为已完整恢复。

磁盘上的项目、未提交改动和 Agent 历史继续由原系统管理。恢复工作区不执行 Git checkout/reset，不回滚代码，也不自动重建已删除的 worktree。缺失目录保留恢复位置和原因，等待用户处理。

## 3. 当前基础与缺口

以下结论来自上述代码基线，不能视为重启恢复已经可用。

| 当前实现 | 可复用部分与缺口 |
| --- | --- |
| [MainView](../CtrlxPackage/Sources/CtrlxServerFeature/Views/MainView.swift) 每 2 秒检查布局变化 | 可以沿用保存节奏；现有任务依附主视图，完整快照应由 App 生命周期持有，覆盖后台会话和独立窗口 |
| [LayoutStore](../CtrlxPackage/Sources/CtrlxServerFeature/Services/LayoutPersistence/LayoutStore.swift) 原子写入 JSON | 可以沿用状态根目录、依赖注入和原子写入方式 |
| [SavedFolderRecord](../CtrlxPackage/Sources/CtrlxServerFeature/Services/LayoutPersistence/SavedFolderRecord.swift) 按主机和目录存储 | 适合新会话的目录默认布局；不能准确区分同目录的多个已有会话 |
| [SavedFolderLayout](../CtrlxPackage/Sources/CtrlxServerFeature/Services/LayoutPersistence/SavedFolderLayout.swift) 按 window index 映射已有终端 | 不重建消失的 tmux session/window/pane；重启恢复需要独立的持久身份和结构记录 |
| [DetachedTerminalWindows](../CtrlxPackage/Sources/CtrlxServerFeature/Models/DetachedTerminalWindows.swift) 管理独立窗口及标签归属 | 状态主要保存在内存；目前有独立标签的会话还会跳过目录布局保存 |
| [AgentSessionIdentityClient](../CtrlxPackage/Sources/CtrlxServerFeature/Services/AgentSessionIdentityClient.swift) 保存原生对话身份 | 当前缓存绑定 PID 和进程启动身份，用于确认仍存活的进程；不能直接作为电脑重启后的恢复器 |
| [PluginCore](../CtrlxPackage/Sources/CtrlxPluginProtocol/PluginCore.swift) 与 [AgentSessionForking](../CtrlxPackage/Sources/CtrlxPluginProtocol/AgentSessionForking.swift) | 已有启动和 Fork 能力；自动 resume 需要明确的可选插件能力 |
| Host Files 与 Chromium 页面 | 当前 Host Files 重启后重新建立共享标签清单，Chromium 页面是临时状态；见 [Files 生命周期](file-browser.md#directories-and-lifetime)和[浏览器文档](agent-browser.md) |

保留两种用途，不用旧目录模板猜测丢失的真实现场：

- **目录默认布局**：用户新建会话时，提供该目录常用的布局。
- **工作现场快照**：重启时，恢复那一次实际存在的会话、窗口和标签。

准确的现场快照优先于目录模板。首次启用只能记录当时可观测的现场，旧模板无法追溯重建已经丢失的 pane 和 Agent 对话对应关系。

## 4. 快照与身份

### 4.1 最小数据模型

建议在现有 CtrlX state root 下保存一份带版本的工作现场快照，并保留上一份完整快照。首版采用 JSON 即可，不引入数据库或多版本快照管理 UI。文件名称和具体类型名在实现时确定。

| 记录 | 必需内容 |
| --- | --- |
| 快照头 | 格式版本、保存时间、快照代次、所属 Host/状态实例、系统启动标识及 tmux 运行实例信息 |
| 会话 | 持久 UUID、名称、显示属性、窗口顺序及选择 |
| tmux window / pane | 各自的持久 UUID、分屏树或等价布局结构、比例、目录、选择状态 |
| Agent 恢复描述 | plugin ID、经确认的原生会话 ID、配置根目录、工作目录及插件能够可靠保存的启动配置 |
| Mac 展示 | 主窗口与独立窗口、窗口位置大小、每个窗口的标签归属、分栏与选择 |
| 辅助标签和草稿 | 标签类型、路径或恢复描述、关联的持久身份、CtrlX 未发送草稿 |
| 未完成恢复项 | 原始恢复描述和当前结果，保证部分失败或中途退出后仍可重试 |

不保存进程内存、终端实时字节流、环境变量全集或凭证副本。Agent 历史文件仍由 Agent 管理；历史被清理后，CtrlX 的身份记录不能代替历史内容。

### 4.2 身份规则

- 为会话、window 和 pane 分配持久 UUID，并在可管理的 tmux 对象上关联这些身份。
- tmux 的 `%pane`、`@window` 和会话名称仅用于当前运行实例内的路由，不能单独用于跨重启匹配。
- 重建后建立“持久 UUID → 新运行 ID”映射，再恢复标签、草稿、独立窗口和 Viewer 路由。
- 多个 session 链接同一个 tmux window 时，只重建一份 window/pane 和 Agent 进程，再恢复各 session 的链接、索引和选择。结束一个 session 不等于结束仍由其他 session 使用的共享 window。
- 对远程对象始终包含 Host 身份；不能把另一台主机相同编号的 pane 当作恢复目标。
- 保存 Agent 描述时核验对话与当前 pane 的实际归属；重启后用描述启动新进程，不放宽现有存活进程缓存的 PID/启动身份校验。
- 来源不明确、重名或其他工具已恢复但缺少可确认身份的对象，不靠名称、目录或数字 ID 猜测合并。

共享终端、Host Files 和各客户端私有展示遵循现有所有权。持久身份是重新关联的依据，不授权 Viewer 用私有快照覆盖 Host 状态。

### 4.3 保存策略

1. 在 App 层持续收集全部已观测本机会话与展示状态，包括未选中的会话、独立窗口中的标签。
2. 每约 2 秒检查一次；仅内容变化时写盘，拖动分隔线和窗口产生的密集变化合并处理。
3. 用户明确关闭标签、结束会话时及时保存。关闭展示窗口、退出 App 和结束 tmux 会话沿用各自现有语义，不能混为删除。
4. 正常退出或收到系统关机通知时，在拆除展示模型和服务前补一次保存；不依赖退出回调作为唯一保存机会。
5. 串行写入、原子替换；写入失败保留上次完整记录。格式不支持或读取损坏时给出可诊断原因，不把失败读取再写成空快照。
6. 启动发现、恢复及关闭清理期间的临时空集合不能覆盖完整快照。部分恢复成功后仍保留失败项的恢复描述，同时允许用户后续编辑已恢复部分。

系统突然断电可能丢失最近尚未落盘的变化，2 秒是正常运行的保存检查目标，不是零丢失保证。关机过程中 tmux 先退出的时序需要单独验证，不能把“已成功读取到空列表”一律当作用户主动清空现场。

快照只在 CtrlX 运行期间更新。用户完全退出 CtrlX 后，在其他终端改变 tmux 布局，首版只能恢复最后记录的现场；不为此增加独立守护进程。

## 5. 恢复流程

### 5.1 触发与判定

| 启动情况 | 行为 |
| --- | --- |
| CtrlX 重启，原 tmux 仍在 | 连接现有终端，恢复展示；不重新启动正在运行的 Agent |
| 系统启动标识变化，存在可恢复快照 | 核对当前 tmux，重建明确缺失的对象，再恢复对话 |
| 同一次开机中会话被用户关闭 | 尊重删除，不因普通 App 重启自动复活 |
| 同一次开机中 tmux 意外退出 | 保留记录并提供显式恢复入口，不把所有会话消失都当作电脑重启 |
| tmux 读取失败或远程 Host 离线 | 保留快照并等待可用，不据此重建或删除对象 |
| 上次恢复尚未完成 | 结合持久身份与实时状态继续核对，已完成项不重复创建或启动 |

普通升级或重启 App 后，即使存在未完成恢复标记，也先读取真实 tmux 状态。同一次系统启动、
同一 tmux 实例且已保存结构完整时，直接复用现有结构，仅核对未完成的 Agent 项。
持久身份一致的普通活跃进程直接保留，结束该项的旧恢复等待；恢复占位 pane 和本次日志中
已经发起、尚待确认的启动继续保留原检查，避免丢失恢复入口或重复启动。
此前已完成恢复的 pane 可能仍带有旧占位标记；与当前日志不匹配的旧启动标记不应产生新的恢复告警。

Mac 恢复详情采用限高滚动列表，标题和收起按钮始终可见。需要人工确认的活跃终端可选择
“Keep All Current Terminals”；操作逐项重新检查当前身份和存活状态，确认目标后保留其当前进程。
过程中已停止的目标继续保留恢复项，批量保留不发起新进程。

### 5.2 执行顺序

1. 读取快照并取得可靠的 tmux 状态，暂缓常规保存覆盖恢复源。
2. 关联现有对象，确认哪些对象需要重建；保留现有真实会话和用户已经进行的操作。
3. 创建所需 session、window 和 shell pane，恢复各目录及终端分屏结构，记录新 ID 映射。
4. 还原主窗口、独立窗口、左右分栏、标签、选中项及草稿。恢复期间显示真实进度，尚未可用的目标不接收发送操作。
5. 等 Agent 插件与相关服务就绪后分批 resume，当前可见目标优先；后台目标继续恢复，避免同时启动大量进程卡住界面。
6. 逐项核对结果；成功项进入正常状态，失败项保留在原位置并提供原因和重试入口。
7. 完成必要的映射与结果记录后恢复常规快照保存，未完成项不能因暂时没有运行进程而被丢弃。

重试必须收敛：相同快照重复恢复、恢复到一半退出再启动，不产生第二份会话、标签或 Agent 进程。发起命令后若结果不确定，先核对实际进程与对象身份；不能直接重发 resume。

### 5.3 局部失败

| 原因 | 用户可见结果 |
| --- | --- |
| 项目或 worktree 目录不存在、磁盘尚未挂载 | 原位置保留“目录不可用”及重试入口；不悄悄换到其他目录启动 Agent |
| Agent 未安装、插件被禁用、历史缺失或身份不明确 | 保留标签并说明原因，可重试或明确选择使用 shell；不自动开启被禁用插件 |
| Agent 需要登录或交互确认 | 在对应终端呈现 Agent 自己的交互，不由 CtrlX 代答 |
| 会话名称冲突或发现其他恢复工具创建的对象 | 保留现有现场，标出冲突，不覆盖或冒认对象 |
| 原显示器不可用 | 将窗口调整到当前可见屏幕范围 |
| 单个标签恢复失败 | 其余会话继续恢复，不用整组失败阻塞工作 |

不逐个弹模态确认框。需要用户介入时，在受影响的标签或恢复结果中集中说明。

## 6. Agent resume 规则

首版适配 Codex 和 Claude Code。调研时本机 `codex resume --help` 与 `claude --help` 确认支持指定会话 ID；实际接入时仍需记录测试使用的 CLI 版本和行为。

| Agent | 原生入口示意 |
| --- | --- |
| Codex | `codex resume <session-id>`，配合原工作目录与正确的 `CODEX_HOME` |
| Claude Code | `claude --resume <session-id>`，保留正确的配置目录语义 |

以上是能力说明，不应直接作为绕过现有命令解析、shell 转义或插件环境配置的实现。复用现有启动路径与历史定位能力，由插件提供可选的 resume 描述；通用恢复协调器不拼接各家的命令行参数，也不要求 sidecar 插件立即升级才能继续使用原功能。

具体约束：

- 使用准确的原生会话 ID；不使用 `--last` 或“当前目录最近一次对话”替代身份。
- resume 延续原对话，不使用 Fork 创建副本；一个标签中的多个 Agent pane 分别恢复。
- 恢复配置来源，避免多账号、多个配置目录或 profile 下串用会话。无法可靠确认的临时启动参数不猜测重放，也不提高原权限设置。
- CtrlX 不附加“继续”，不重发上一条提示词、工具调用、命令或旧审批。
- Working、通知、Questions 和审批状态以新进程的有效事件重新建立；历史中的旧请求不能成为可提交的新请求。
- 是否恢复已有 Agent 对话由恢复设置决定，不能简单复用“新建会话自动运行 Agent”的开关；插件被禁用仍须尊重。

原生 resume 可能运行启动钩子，部分 Agent 模式也可能自行继续任务。因此“CtrlX 不代发继续”不等于“Agent 一定停在空闲输入状态”。自动恢复前需验证支持版本中空闲、任务中断和等待审批等场景；行为未经确认的插件或模式只提供显式恢复入口。

## 7. 多端职责

- **Host Mac**：保存并恢复本机 tmux 结构、Agent 和共享对象，发布恢复后的实时身份与状态。
- **Mac Viewer**：重新连接 Host，恢复自己的窗口归属和私有查看状态；不能因为 Viewer 自己重启就再次启动 Host 的 Agent。
- **iOS**：重新连接并关联恢复后的会话/pane，恢复适合手机的选中项与私有状态；不在手机构造 Agent 命令。
- **Relay**：沿用现有加密路由职责，不承担工作现场恢复执行。

Host 原来已共享的终端布局继续以 Host 为准，不引入全设备桌面布局同步。远程路径只在 Host 解释；离线时保留恢复记录。新增跨重启身份映射若需要 wire 字段，必须使用可选字段和能力协商，验证旧客户端兼容，不把旧编号碰巧相同当作映射成功。

## 8. 设置与实现边界

设置页增加“启动时恢复工作现场”，提供三个模式：

1. **布局、终端与 Agent 对话**：建议默认模式，对已验证的 Agent 自动 resume。
2. **仅布局与终端**：恢复结构和 shell，Agent 位置保留手动恢复入口。
3. **关闭**：不使用本功能重建上次现场；现有 tmux 会话发现和连接照常工作。

“登录自动启动”沿用现有设置。默认在用户登录后 CtrlX 启动时执行恢复，不增加用户登录前运行的系统服务。恢复开关不隐式删除已有快照。

实现优先复用现有 tmux 操作、布局值类型、状态根目录、插件启动及历史定位能力。在 App 生命周期内增加一个恢复协调层，统一保存和启动恢复，避免给每个窗口各自增加恢复器。只持久化可序列化描述，不保存 SwiftUI View、NSWindow、终端视图或浏览器运行对象。

不要求用户额外安装 tmux-resurrect；可以借鉴其结构恢复方式，但 CtrlX 自身的分栏、独立窗口、草稿和 Agent 身份仍由本功能统一处理。
