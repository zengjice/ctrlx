# Orbie 待决策与验证项

记录日期：2026-11-13。下表是实施前的假设与验证事项，**不是已复现的缺陷或已通过的验收**。主线见[实施计划](IMPLEMENTATION_PLAN.md)。

| ID | 问题 | 当前建议 | 何时收敛 |
| --- | --- | --- | --- |
| O-01 | 指定 Host 是否作为首版固定拓扑 | 先支持本机显式启用，不做自动选主；其他设备通过现有 Viewer 使用普通标签 | 阶段 1 开始前确认产品边界；具体机器由用户启用时选择 |
| O-02 | 首发 Agent 与单步投递是否适配日常对话 | 先 Codex 后 Claude，共用能力接口；用户选择 Provider。必须验证提问、人工接管与首轮会话绑定 | 阶段 1 验证；不支持的插件不冒充可用 |
| O-03 | 全局快捷键与焦点规则 | 用户可配置；冲突时保留菜单入口，不强占系统常用快捷键；结果不自动激活面板 | 阶段 3 实现前确定默认键及多屏验收样例 |
| O-04 | 原生 CLI 指令、原生记忆与产品记忆的交界 | 保留现有原生设置；项目 cwd 与材料目录分开，显式传入相关文件，不许诺完全记忆隔离 | 阶段 1 记录所测版本，阶段 5 接入前核对实际行为 |
| O-05 | 并发、运行额度与存储保留 | 建议试用上限两个活跃 Orbiter 任务，主对话一次一条；不排队、不新增通用计费器、不自动删除产物 | 阶段 2 确定并发默认值；阶段 6 用资源数据决定后续额度／保留策略 |
| O-06 | 哪些选区入口有可靠内容和来源 | Terminal／Files 文本先行，Browser／Simulator 用已有截图标注；外部 App 主动粘贴，Services 单独验证 | 阶段 4 逐入口验收，不以一个入口通过代表全局支持 |
| O-07 | 重启、写入不明与已关闭任务的接续 | 复用已有账本和 workspace recovery；无证据不重复投递，也不凭标题找新目标 | 阶段 1、2 回归；阶段 6 隔离故障验收 |
| O-08 | 内部单步执行记录的展示与保留 | 复用工作流记录与历史入口，任务索引仅保存关联；不为隐藏记录另造工作流类型或第二份账本 | 阶段 2 确定列表呈现和归档联动，保留有引用的执行结果 |
| O-09 | 实际交付版本及后续自动化 | 本目录只组织计划；先验收核心闭环，词库／Dreaming 以独立证据决定投入 | 发版另行确定；后续功能不作为当前开发已获授权的推论 |

后续发现的问题在这里补充复现条件、影响、阶段及证据；关闭时关联对应改动和验证记录，不用「已处理」代替依据。实际开发开始后，已确定的默认值应同步到设计方案，避免长期保留两套说法。
